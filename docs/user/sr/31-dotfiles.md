# Dotfiles

Arch се првенствено конфигурише кроз такозване dotfiles који живе у `~/.config`. То се сматрају вашим датотекама за ваше промене. Датотеке које живе у `/usr/share/arch` припадају самом Arch-ју и не бисте требали да се петљате са њима. Ако треба да промените било шта у `/usr/share/arch`, требало би да вредност уместо тога препишете у `~/.config`.

Кључне конфигурације могу се уређивати директно из Arch менија (`Super + Space`), попут _Подешавање > Монитори_, _Подешавање > Пречице_, _Подешавање > Унос_ и _Подешавање > Config > [file]_. Када то радите на овај начин, сваки процес који треба поново покренути након уређивања конфигурације аутоматски ће бити поново покренут када изађете из уређивача (Neovim подразумевано — `:wq`, запамтите! — али то можее променити преко _Подешавање > Defaults > Editor_).

Ево списка кључних датотека у `~/.config` и шта контролишу:

| File                  | Purpose              |
| ----------------------- | --------------------- |
| `~/.config/hypr/hyprland.lua` | Главна Hyprland конфигурација. Учитава Arch подразумеване вредности плус ваше датотеке за преписивање испод. [Сазнајте више о Hyprland конфигурацијама](https://wiki.hypr.land/Configuring/).  |
| `~/.config/hypr/bindings.lua` | Ваше сопствене пречице и преписивања подразумеваних. |
| `~/.config/hypr/monitors.lua` | Контролише ваше мониторе, резолуцију и положај. |
| `~/.config/hypr/input.lua` | Контролише распоред тастатуре, миш и подешавања тачпеда. |
| `~/.config/hypr/looknfeel.lua` | Контролише размаке, ивице, анимације и остатак изгледа. |
| `~/.config/hypr/autostart.lua` | Контролише додатне процесе покренуте са сесијом. |
| `~/.config/arch/shell.json` | Контролише Arch љуску: положај траке, распоред и виџете, плус времена чувара екрана, закључавања и мировања. |
| `~/.config/foot/foot.ini` | Контролише ваш терминал (foot је подразумевани). |
| `~/.XCompose` | Дефинише ваш брзи приступ емоџијима и аутокомплетирање имена/е-поште. Обавезно покрените `arch-restart-xcompose` након промена. |

Ако на крају направите много промена да бисте подесили сопствену поставку, добро је да направите резервну копију свих ових dotfiles-а. [Stow је одличан начин за то](https://www.youtube.com/watch?v=NoFiYOqnC4o).

### Покретање сопствених апликација са сесијом

Ако желите да се нешто покреће сваки пут када се пријавите — демон за синхронизацију, апликација за ћаскање, ваш сопствени скрипт — ставите то у `~/.config/hypr/autostart.lua`:

```lua
o.launch_on_start("my-service")
```

То покреће команду као део сесије, па се правилно чисти када се одјавите.

### Покретање скрипти на системске догађаје

Arch окида куке у неколико тренутака и на њих можее окачити сопствене скрипте. Живе у `~/.config/arch/hooks/<event>.d/`, по један директоријум по догађају, а свака извршна датотека тамо се покреће када се догађај деси:

| Event | When it runs |
| ----- | ------------ |
| `post-boot` | Одмах након покретања радне површине |
| `post-update` | При крају `archctl update`, након пакета, миграција и поновних покретања сервиса, пре ажурирања mise алата |
| `pre-refresh-pacman` | Након што `archctl refresh pacman` поново синхронизује конфигурацију пакета, пре ажурирања пакета; промена канала га покреће током истог корака освежавања |
| `theme-set` | Након промене теме (име теме у `$1`) |
| `font-set` | Након промене фонта (име фонта у `$1`) |
| `battery-low` | Када се батерија испразни (проценат у `$1`) |

Кука `pre-refresh-pacman` је место где припадају прилагођени репозиторијуми или линије `IgnorePkg`, јер се покреће пре трансакције пакета. Обе куке у вези са ажурирањем извршавају се као ваш корисник након што Arch обрише кеширану sudo ауторизацију, па кука која користи `sudo` треба сопствену ауторизацију и може тражити лозинку.

Сваки од тих директоријума већ садржи `.sample` датотеку која показује облик куке — уклоните `.sample` из имена да је ставите у рад. За инсталирање скрипта који сте написали негде другде користите `archctl hook install post-boot ~/my-hook`, што га копира и чини извршним.

### Додавање сопствених уноса у мени

Arch мени (`Super + Space`) може се проширити сопственим редовима уређивањем `~/.config/arch/extensions/arch-menu.jsonc`. Уноси су кључани тачкастим id-јем, а id је оно што их смешта у стабло, па се `personal` појављује у коренском менију, а `personal.notes` унутар њега:

```jsonc
"personal": {"icon":"","label":"Personal"},
"personal.notes": {"icon":"󰎞","label":"Notes","action":"arch-launch-editor ~/notes"},
```

Поново користите постојећи id и уместо додавања новог преписујете тај ред. Датотека долази са свим доступним пољима документованим као коментари.

### Додавање сопствених shell извоза, функција и алијаса

Arch долази са гомилом ергономских алијаса и корисних функција, али је веома често желети додати сопствене. И алијасе, функције и извозе треба додати у `~/.bashrc`. Ова датотека неће бити преписана при ажурирањима. Ако желите да промените било коју Arch подразумевану вредност, можее их безбедно додати и овде.

### Мењање унутрашњих Arch датотека

Гледајте, ово је ваш рачунар. Можете радити шта год желите са њим, али саветовао бих да не мењате датотеке у `/usr/share/arch` директно. Оне припадају Arch pacman пакету, па ће ваше промене једноставно бити преписане при следећем ажурирању. Боље вам је да само препишете све подразумеване вредности које вам се не свиђају у фасцикли `~/.config/*`.

На тај начин можее променити готово све, попут подразумеваних пречица. Једноставно уредите `~/.config/hypr/bindings.lua` да, рецимо, замените [Obsidian](https://obsidian.md/) са [Joplin](https://joplinapp.org/) (инсталирајте помоћу `arch-pkg-add joplin-bin`):

```lua
o.rebind("SUPER + SHIFT + O", "Joplin", "joplin-desktop")
```

`o.rebind` уклања постојећу везу пре додавања њене замене. Прима исте аргументе као `o.bind`, укључујући помоћнике за покретање и опције везивања. Користите `o.bind` да додате везу или `hl.unbind` да је уклоните без замене.

Ако инсистирате на хакирању унутрашњих Arch датотека, пребаците се на dev канал преко _Ажурирај > Channel > Dev_. То повезује Arch са git чекаутом изворног кода у `~/arch`, који слободно можее мењати до миле воље. Овде нема никога да вам каже шта да радите!

### Ресетовање свих промена

Ако на крају направите збрку са конфигурацијама, увек их можее вратити на подразумеване преко _Ажурирај > Config_ у Arch менију. Или покретањем `arch reinstall configs` да ресетујете све.
